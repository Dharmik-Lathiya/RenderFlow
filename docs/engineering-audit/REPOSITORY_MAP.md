## 3. Request / data flow

```
Browser (Next.js)  ── REST + SSE ──▶  api (NestJS, /api/v1)
                                          │  guarded by rate-limit → CSRF → auth/RBAC
                                          ▼
                                    PostgreSQL (source of truth + outbox)
                                          ▲                    │
                          outbox-relay (SKIP LOCKED) ──▶ Redis/BullMQ
                                                             │
                  content-worker ── stage events ──▶ media-worker
                  publisher-worker (DB poll + delayed jobs) ──▶ social adapter (mock by default)
                  analytics-worker ──▶ post_metrics
                  reaper ──▶ leases / requeue / refunds
                                          │
                                     S3 / MinIO (assets, renders)
```

Dependency direction: `apps/* → libs/*`, never the reverse; apps never import each
other. Tenancy is enforced in services (`WorkspaceAccessService.scope()`), not a
route guard, because resource ids live in the body/params.

## 4. Database relationships (from `libs/db/src/schema.ts`)

Core clusters:

- **Identity**: `users → wallets`, `credit_ledger`, `refresh_sessions`, `auth_tokens`, `audit_logs`.
- **Tenancy/content**: `users → workspaces → workspace_members`; `workspaces → brands → campaigns → posts → assets`; `brand_memory → brands`.
- **Generation**: `generation_jobs → job_checkpoints`, `outbox_events` (aggregate `JOB`), `posts`.
- **Publishing**: `posts → publish_jobs → social_accounts`, `post_metrics`; `social_accounts → workspaces`.
- **Festival**: `festival_occasions → festival_templates`.
- **Notifications**: `notifications → users`, deduped.

Credit-critical constraints live in schema: wallet `CHECK (available >= 0 AND reserved >= 0)`,
`credit_ledger_signup_bonus_once` partial unique index, `credit_ledger_reference_key`
unique `(reference_type, reference_id, entry_type)`, and a CHECK forbidding a job
being both captured and refunded.

Migrations: `0000` initial, `0001`, `0003` phase-3 workspaces, `0004` legacy column
defaults, `0005` checkpoints, `0006` outbox dedupe key, `0007` brand memory, `0008`
publishing, `0009` notification dedupe, `0010` publish partial index, `0011`–`0013`
recovery/auth tokens, `0014` publish post id index, `0015` refresh session family,
`0016` connections + festival countries.

## 5. Queue / worker relationships

| Queue           | Producer                                            | Consumer                       | Stages/events                |
| --------------- | --------------------------------------------------- | ------------------------------ | ---------------------------- |
| `content`       | outbox relay (`job.created`, stage completions)     | content-worker                 | PLAN, SCRIPT, festival copy  |
| `media`         | outbox relay (stage completions)                    | media-worker                   | IMAGE, VOICE, RENDER         |
| `publish`       | outbox relay (`post.scheduled`), DB poll safety net | publisher-worker               | delayed publish jobs         |
| `analytics`     | outbox relay (`post.published`)                     | analytics-worker               | wake-up; DB poll is schedule |
| `notifications` | publisher/failure paths                             | in-app writer + email bridge   | failure mail                 |
| `dlq`           | exhausted jobs/events                               | admin console (inspect/replay) | logical queue, no table      |

Stage hand-off: `queueForJobStage()` in `libs/common`; a worker refuses a job whose
next stage it does not own.
